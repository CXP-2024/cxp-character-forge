# 眼睛与眉毛表情：Charakuru 方法与参考对照

适用：在已认可角色上制作眨眼、单眼闭合、情绪眼与眉部表情，并接入已有舞蹈 VMD。眼白、虹彩、高光的组件与材质整理另见 [eye-refinement.md](eye-refinement.md)；通用保形规则见 [facial-expressions.md](facial-expressions.md)。

## 两条主线

**Charakuru 提供保留原脸的拟合、局部迁移与可编辑工作键；参考角色提供表情运动和视觉完成度的目标。两者都不能省。** 迁移成功不等于表情合格，参考相似也不能以改变目标角色脸型为代价。

DeepSeek / 奥黛塔任务的明确约束：DeepSeek 原脸型不能变；始终左奥黛塔、右 DeepSeek，对照灰模与最终材质。奥黛塔用于比较开合规律、眼角、闭眼弧线及眉部情绪，不复制她的脸宽、鼻梁、眼距或眼窝。其他项目按用户指定参考与身份约束执行。

## 1. 固定基线与实际需求

- 记录用户认可的工程及模型版本，原件只读，另存候选。不能按文件版本号最高就认定为已验收版本。
- 记录 Basis、原有形态键、面索引、UV、材质、权重、变换和驱动关系。新增工作键，局部修形落在工作键；全键归零应回到原脸。保护鼻梁、脸颊、下颌及非目标区域。
- 先解析目标动作实际有非零权重的 morph 轨道，再决定制作顺序；VMD 名称按 CP932 解码，保留原名、时间、权重和左右。只有零值的轨道不算实际需要的表情。
- 分开标记“已有键”“视觉通过”“已映射原动作”“组合动画通过”。同名或存在驱动不证明语义正确，不能把所有表情都说成已接准。
- 眼白/虹彩组件更新后重新核对对象、拓扑签名、地标与选区，旧顶点编号不能跨模型直接套用。

## 2. 核对 Charakuru 源码与眼部选区

源码入口（Release 解压的 kit 目录）：`<kit>/skills/avatar-expression-authoring/SKILL.md`，按需读其 `references/transfer.md`、`anatomy.md`、`diagnostics.md`、`visual-quality.md`；实现为 `kit/scripts/expression-studio.py`、`expression-mask.py`、`expression-transfer.py`。这是本机已核对来源，不代表远端永远无更新；版本变化时按实际签名调用。

1. 先看带发自然脸，再分开看皮肤、实际眼洞、睫毛、眼睑线、眉毛、眼白、虹彩和高光。灰模/线框核实结构，材质图核实观感。
2. 确认角色前上轴和左右；Charakuru 的 L/R 遵循相机基准，L 位于画面右侧，不凭世界 X 正负命名。
3. 每眼四点 `eyeInnerL/eyeOuterL/eyeUpperL/eyeLowerL` 及对应 R，取**皮肤实际开口边**的世界坐标，不用瞳孔边界或睫毛尖代替。
4. skin seed 可能选中连到身体的皮肤组件；组件连通不代表全部都是眼周。检查归一化尺度、世界坐标影响区、保护顶点，正面和侧面都确认。
5. followers 明确选择需要追随的睫毛和眼睑线；普通眨眼不带眉。连通块大小、颜色阈值、材质名不能单独充当语义分类，尤其是睫毛与脸皮融合、窄三角形只有部分 UV 顶点呈深色的情况。

示意调用（对象、seed、坐标和 followers 必须来自当前模型）：

```python
helper.prepare_blink(OBJECT, skin_seed=SKIN_SEED)
helper.set_blink_points(POINTS)
helper.set_blink_followers(FOLLOWERS)
helper.fit_blink()
helper.capture_fit(angles=['Front', 'Oblique45', 'Profile90'])
# 实际查看拟合图后才设置 reviewed=True
helper.transfer_blink(reviewed=True)
# 或只迁移当前需要的少数键：
# helper.transfer_eyes(expressions=['blink', 'happy_eye'], reviewed=True)
```

## 3. 闭眼先做透，再扩展情绪眼

- 先完成双眼 blink 的连续开合，再做左右单眼、笑眼，最后按目标动作补其他情绪眼。公共拟合有问题时不要批量生成全部键。
- 上睑主导、下睑少量运动可从约 90/10 开始，再按原脸和参考调整。位移分散到多行相邻皮肤，眼角渐弱；保留睫毛厚度，不把整条睫毛平移或压成薄线。
- 八点拟合不解决深度：Charakuru 源 blink 主要上下运动，前后变位近零。检查斜侧面，让眼睑符合目标面部曲率，睫毛贴合但不埋入皮肤。
- 灰模的折痕、翻面、针状面、眼角拉裂需要局部几何修形；先判断深度/跟随，再决定是否局部平滑。禁止用全脸平滑、整片眼区压扁、宽范围缩放或参考拓扑直接替换来凑相似度。
- 眼白、虹彩、高光和眼睑遮挡一起验收。不要默认沿用旧闭眼时眼球平移补偿，也不要未经对照就删除；看半闭与全闭、左右斜视是否穿出或消失。不能靠整体挪走眼球掩盖眼睑错误。
- 单眼键需验证另一眼及眉不被带动；左右拓扑不对称时不能假设顶点一一镜像。

## 4. 眉毛独立迁移，必要时带动眉下皮肤

```python
helper.prepare_brows({
    'L': {'object': OBJECT_L, 'seed': BROW_L},
    'R': {'object': OBJECT_R, 'seed': BROW_R},
})
helper.transfer_brows(reviewed=True)
```

先对照参考检查眉头/眉尾方向、弧度、高度、左右关系，再检查目标角色神态。皮肤或绘制眉确实需要跟随时，按当前源码使用 `skin={'object': HEAD, 'seed': SKIN_SEED}`、`protected=EYE_RIM_IDS`、`support=.8`、`full=.36`；后两者是眉宽比例的起点，不能当通用固定范围。保护实际眼洞边，按连接距离衰减；眉下出现台阶就重新调整。

不要把眉与眼睑一起绑给最近邻驱动，容易拉长上睑。融合眉可局部编辑，不默认切开。出现双眉/双眼睑线时先区分贴图重复与网格跟随不完整，不能一律擦纹理。

Charakuru 眼部源姿势含 `happy_eye, angry_eye, sad_eye, relaxed_eye, surprised_eye, blink, blink_L, blink_R`；眉部含 `happy, angry, sad, relaxed, surprised`。MMD 的 `真面目、にこり、下、困る、怒り２` 等需看参考实际变形建立语义对应，不能只凭译名映射。

## 5. 始终左右对照的验收循环

每轮按“定位一个差异 → 修改候选工作键 → 同条件重出图 → 检查保形 → 留下结论”推进。

- 固定左参考/右目标；每个强度 0、0.25、0.5、0.75、1 分别排灰模和最终渲染，清楚标出键名、强度、候选版本。不能只有目标图。
- 对齐观察角度、展示尺度、灯光与色彩管理；保留各自原脸比例。裁图只方便观察，不把裁图对齐宣称为几何配准或“99% 相似度”。
- 比较眼洞开口、上下睑运动比例、内外眼角、闭眼弧线、睫毛厚度、眼睑线跟随和眼球遮挡；眉部比较眉头/眉尾运动及情绪。保留目标角色身份差异。
- 正面之外看左右 45° 和侧面；带发/去发、局部近景/正常镜头都检查。参考角色灰模若没有独立眼球显示，不据此要求目标移除眼球。
- 做 blink+眉、单眼+笑、眼眉+张嘴的组合和连续变化。单键通过不证明叠加后没有拉扯、双线、穿透或闪动。
- 保存后重新打开，验证工作键、驱动、原动作帧与归零。保形检查至少输出 Basis/原键最大位移、拓扑/UV 是否一致、目标区域外位移；视觉检查单独记录。数值通过不能替代视觉通过。
- 用户要求近乎还原时，用这些可见差异逐项收敛；未定义可比较指标时不要报告虚构百分比，未通过候选不能覆盖正式工程。

## 6. 本地已遇到的问题与恢复方法

| 症状 | 排查与处理 |
| --- | --- |
| 眼窝、鼻梁或脸颊随“优化”变形 | 回到认可原脸，废弃改变 Basis/宽范围皮肤的候选；仅在新工作键局部重做。DeepSeek 的参考眼区拼接与大范围平滑试验已放弃，不能复用为成功方案。 |
| 全闭细缝、红色眼睑线脱离、睫毛针刺或折角 | 分开检查开口边、眼睑线、睫毛连通与 UV 面，再检查深度；不能只靠最终材质遮盖或把睫毛整体压平。 |
| Charakuru 报“通常顔へ戻らない” | 记录归零最大误差，检查实际变形、动画重求值、单位与组件尺度。只在诊断副本暂停并记录 action/drivers/NLA，不删除正式动画。 |
| 归零守卫被微小精度误差触发 | 本地曾测得 1.66893e-6 m，而误用 scale=.15 使阈值为 1.5e-6；按真实选中组件重新计算尺度后通过。必须同步换算归一化区域，保持世界空间选区不变并重看拟合；不能任意增大 scale 或关闭守卫过关。 |
| 渲染诊断后工作工程的相机/动作状态改变 | helper 可能在退出时自动保存；检查源码保存行为，QA 使用独立副本/进程，避免退出覆盖制作状态。 |
| 换基线后 session 与工作键不匹配 | 新基线使用新会话目录，重新记录签名和选区；不要把旧 attach 状态强行接到不同模型上。 |

## 项目续作记录（2026-10-29，非通用参数）



该项目优先顺序为眨眼 → 左右 wink → 笑眼 → QueenCard 实用眉形 → 原 VMD 组合验证 → 星目及爱包额外表情。两套舞蹈及不同角色 VMD 所需键不同，重新解析实际文件；本文不把某一舞蹈的键表作为所有动作的标准。

# Houdini 裙子与头发：本地可复用经验

用于已有角色的离线衣发解算与 Blender 接回。整首分段、拼接与远端安装授权见 [houdini-fullsong-remote.md](houdini-fullsong-remote.md)。先读 [rigging-physics.md](rigging-physics.md) 校准骨架、动作和验收范围。本记录来自 Claude V21–V25；不把试片参数或后处理当作所有角色的标准方案。

## 运行与坐标契约

- 已实际使用 `hython` 和 `blender -b -P` 完成无界面流程，无需 Computer Use。先探测本机安装、许可类别、节点和参数，再做小型解算—导出—导入测试；安装成功不等于批处理许可可用。
- 当时环境为 Houdini 22.0.466、Blender 5.2.1；观测到 `hou.licenseCategory()` 返回 Indie。该观测不能证明未来机器的许可、商业用途或导出权限，不能据此承诺免费许可具备所有能力。
- 本项目 Blender 为 Z-up、正面 +X，Houdini 为 Y-up：`(x,y,z) -> (x,z,-y) * S`，返回时取逆。Claude 使用 `S=1.7`；其他角色先检查真实尺寸。碰撞厚度、重力和刚度应按实际单位调整。
- 导出评估后的世界坐标；写 Blender 本地顶点缓存前乘对象世界矩阵的逆。绝对缓存启用时停用该对象的 Armature 变形，保留其他对象的动作。
- MDD 顶点顺序必须与接收网格一致。删除裙面时若还要复用整身缓存，保留顶点编号；若裁去无用顶点，先建立稳定映射，同时裁剪缓存并验证重映射后的坐标和 UV。

## 裙子：形状、碰撞和腰部跟随

### 不用碰撞包络替代柔软布料

曾用向外撑开的包络减轻穿模，结果裙子在静止或抬腿时鼓成球状。遇到这类问题先检查碰撞体大小、静止间距和约束，不继续增大外扩量掩盖穿插。

直接解算生成网格也可能失败：烘焙在形状里的褶皱、重叠内外层、非流形边和游离小片会导致展开、碎裂或掉到地面。清理并统计拓扑后，必要时建立连续的低分辨率模拟裙层，再把原带 UV 的外观网格绑定到模拟面；不要为了物理重新生成整个人物。

Claude 的可用试片采用内衬、主裙和外裙代理层，用最近三角面的重心坐标及局部切向/法向偏移带动原裙面。饰品按语义附着，不让最近面搜索跨到不相关裙层。三角面很瘦、翻转或切线退化时，偏移重建会不稳定，需要检查绑定距离和退化面。

### 舞蹈必须有动态锚点

- 独立抬腿时固定裙腰可用；真实舞蹈要让裙腰目标随骨盆的平移和转动更新。只模拟局部坐标再整体旋转，不能宣称保留了完整世界空间惯性。
- 预热时保持舞蹈第一帧姿态，随后连续求解实际动作。碰撞体和锚点使用相同的帧偏移、帧率与坐标变换。
- 使用运动中的腿、身体和地面碰撞，避免用过大的静态球体撑开裙形。在子步、碰撞迭代和厚度之间调节，以抬腿和转身的实际画面判断。
- 弯腰时上衣可能受 spine/chest 影响，而模拟裙腰只跟 hips。处理衣裙接缝时可以让渲染裙面靠腰部分连续过渡到原蒙皮位置，下方仍使用模拟；记录这个混合区域。

### 模拟面通过，不代表最终裙面不穿模

原裙面相对模拟面有厚度、褶皱和绑定偏移，渲染三角形内部仍可能穿腿。Claude 试片采用线性细分提高渲染裙面分辨率，再针对实际腿表面做局部法向接触修正；这属于 Vellum 之后的修正，不是纯求解器结果。

这类修正应限制作用区域和幅度，并检查时间连续性。最近表面法向不等于可靠的全局内外判定，不能把负点积或零报错视作“完全无穿模”。不要用很大的投影量重新制造鼓包。保留修正前结果和逐帧修正统计；需要更准确接触时改进模拟代理、绑定或碰撞表达。

## 头发：避免硬头壳与散发断层

- 先识别后发、刘海、侧发及其真正连接关系。不要按一个统一高度把头发切成固定和自由两半，也不要把所有连通块的最高点自动认作正确发根而不看模型。
- 在现有连通表面上，从选定发根计算沿网格的距离，用连续函数分配跟随强度与允许位移。发根稳定，中段逐渐释放，发梢更自由；刘海、侧发和长后发分别调节。
- 抬手、低头、转头都要检查。第一轮 Claude 原始解算出现刘海被推开、头顶变形和发尾过度散开的现象，不能只凭“能动”验收。
- 可使用连续的动画/模拟混合、平滑位移场和柔和的摆幅限制来保持角色轮廓。对位移而非原顶点位置做平滑，避免把原卷发抹直；发根保持锚定。记录这些步骤，不能把经过限幅和混合的结果描述为完全自由的物理。
- 形状保持混合会重新引入身体接触问题，也可能压缩或拉长局部边。检查发束宽度、边长变化、刘海覆盖、帧间跳动和后脑过渡；不能以根部误差为零代替这些检查。
- 原有发束已交叠时，自碰撞可能导致初始爆开。可以先关闭它定位问题，但要明确“未处理发束间自碰撞”；关闭并不表示穿插已解决。身体/头部碰撞也不保证所有抬手接触自然。

## Vellum 参数与实现陷阱

以下为本机版本的实际诊断结果，换版本或节点配置时重新探测，不盲用参数名或公式。

- `vellumconstraints` 的点组选择需匹配 `grouptype='points'`。把点组名填入默认面组选择曾导致没有生成预期软 pin；检查输出约束的 `type` 数量，而不是只检查参数已设置。
- 软 pin 使用 `pintype='soft'`、`matchanimation=1`，检查输出 pin 的 `matchanimation` 值。实际不需要朝向约束时设置 `pinrotation='none'`，避免额外锁住整片头发方向。
- 刚度有数值与指数两部分，例如 `stretchstiffness` / `stretchstiffnessexp`。需要明确绝对量时显式设置指数，并检查输出的实际 `stiffness`；只填 `1e7` 而沿用指数可能把约束放大许多数量级。
- 本次 soft pin、基值 1、指数 0、属性缩放配置中，属性值 `a` 得到的实际刚度观测为 `2**a - 1`。直接填约 76 得到约 `1e23`，不是 76；改用 `log2(1+k)` 后输出才匹配目标 `k`。这是特定节点配置的实测映射，其他配置仍需抽样验证。
- 自定义渐变属性使用独立名称（本次为 `follow_strength`），避免与求解器的 `targetstiffness` 等语义属性混用。同时检查硬根点、软跟随点和输出约束数量。
- 固定拓扑不应在每个时间步用 Python 重新创建全部点和面。先缓存带组与属性的拓扑，逐帧仅用 `setPointFloatAttribValues('P', ...)` 更新坐标。本次同时调整线程数后明显提速；不要把这一组合结果归因于单一参数或承诺固定加速倍数。
- Python 脚本不要命名为 `inspect.py` 等标准库名；本次它遮蔽标准库并导致 NumPy 导入失败。嵌入 Python SOP 的 Windows 路径优先使用正斜杠，避免字符串转义破坏路径。

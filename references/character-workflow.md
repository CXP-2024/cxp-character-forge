# 参考驱动的分件人物

来源（核对于 2026-10-19）：
- [Tripo 官方 GPT-6 Astra 角色流程](https://www.tripo3d.ai/blog/gpt-6-astra-3d-character-workflow)
- [Tripo 官方 P2 游戏角色教程](https://www.tripo3d.ai/blog/mesh-game-character-p-2)

下面的阶段顺序依据官方教程；地标记录、手部检查与 MMD 要求是本地质量控制补充。官方页的角色图片、问候动画和面部特写是分开的展示资产，不能当成同一次生成的端到端质量保证。

## 参考与生成

保存用户选定的完整设计，分清官方角色设定、社区设计和生成式参考。为穿衣身体、无发头、头发及随附头饰分别准备清晰输入。隐藏表面属于补全假设。拆件不要改变原角色胸腰、脸型或发型；以眼线、下巴、领口、腰线、裙摆和鞋底核对比例。画布尺寸不能代表物理尺度。

姿态需使四肢、颈部、手指可读。多视图必须是同一姿势，不能把侧面垂臂图与正面 T 姿当作同一物体。图像生成后的文字标签不能证明视图一致。按可靠性选择单图或多图；反复重绘仍不收敛时保留原参考约束，进入可控的局部网格修正，不宣称已精确复刻。

生成选项以当前代理 models 和 OpenAPI 为准。官方 Studio 的局部修复、拓扑或 UV 功能未必在代理开放；不要猜测不存在的端点。生成后逐件与完整设计比较，保留原始资产和修改副本。

## 装配与校准

Body、Head、Hair 分别命名、保留可选。以身体确定尺度，头对颈、发对头，检查正侧背的接缝与整体轮廓。无需先把所有物体强制合并；连续皮肤如需焊接，要处理接缝拓扑和法线，独立头发/服装可以共用骨架。

保留有效 UV、材质、骨架。姿势调整优先骨骼或局部旋转；不要以全局按高度压缩网格替代关节旋转，避免弯曲手臂轴。刘海局部形状错误应修发束，不以整体平移头发掩盖。

## 灰模与运动验收（本地补充）

几何不稳定时可先输出无纹理灰模预览。这是审查模式，不代表自动 UV 或贴图功能不存在。输出正、侧、背与左右手近景，查看：
- 肩、肘、腕连续；手掌厚度与腕部过渡正常，无扭转、瘪陷。
- 每手五指、拇指根和其余四指分明；指缝不粘连，袖口不代替皮肤手腕。
- 裙下、腋下、颈口与隐藏区域没有意外封堵或缺面。

无骨架的静态灰模只能验证静态几何，不能声称动作通过。复用可用身体骨架，将头发和头部接入同一骨架；否则新建骨架。检查抬臂、屈肘、转头、屈膝，手部追加握拳/张手，再做短动作。失败按局部几何、权重、骨架方向分别处理。

## 材质、表情与交付

保留已有正确贴图；几何改变导致 UV 不适用时再展开或烘焙。三渲二需检查纹理固有明暗、材质分区和脸部阴影，不能把自动 PBR 直接等同于目标风格。

连续眨眼、口型需要实际眼睑、口腔与可变形面部拓扑；仅有命名滑块不算完成。MMD 还需骨骼命名/映射、IK、手指权重、表情及衣发物理。区分已完成的静态外形、UV、骨架、运动与物理状态，逐项报告实测结果及残留差异。

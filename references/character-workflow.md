# 参考驱动的人物建模：推荐路线与经验

来源（核对于 2026-10-19）：
- [Tripo 官方 GPT-6 Astra 角色流程](https://www.tripo3d.ai/blog/gpt-6-astra-3d-character-workflow)
- [Tripo 官方 P2 游戏角色教程](https://www.tripo3d.ai/blog/mesh-game-character-p-2)
- [Charakuru](https://github.com/nanocle/Charakuru)：从一张立绘做到可动 VRM 的完整套件，包括部件图、三视图、Tripo 候选、重贴图、素体权重迁移、表情和摇摆物理。方法和源码入口见 [charakuru-methods.md](charakuru-methods.md)。

下面的路线来自本地 DeepSeek 鲸娘多轮制作（2026-10-19 至 10-29）的实际结果，不是官方逐步保证。官方页的角色图片、问候动画和面部特写是分开的展示资产，不能当成同一次生成的端到端质量保证。

## 0. 先装好 Charakuru 源码

开始造新角色前，先确认本机有 Charakuru 源码：

1. 到 GitHub Releases（`nanocle/Charakuru`）下载最新发行版 zip，解压到一个独立的 kit 目录，不要在只读参考副本里制作。
2. 准备运行环境：Node.js 22 以上（启动不需要 `npm install`）、Blender 5.2、VRM Add-on for Blender。Blender MCP 可选，没有时用无界面 `blender -b --python` 执行它自带的脚本，并如实说明。
3. 阅读入口：`AGENTS.md`（写给 Codex 的流程、确认点和保存规则）和 `skills/` 下的 9 个 skill。用 Claude Code 时，在 kit 里加一个 `CLAUDE.md`，写明工具名对应关系（image_gen → 本机生图 skill，浏览器操作 → Claude in Chrome，Blender MCP → 无界面 Blender）。
4. 需要用它的界面时，在 kit 目录 `npm start`，打开 `http://127.0.0.1:8766`。

版本号、素材许可和第三方说明见 kit 里的 `LICENSE` 和 `THIRD_PARTY_NOTICES.md`。复制或发布之前先核对；不要把它的人体、表情素材打包进其他仓库。

Charakuru 用作**方法和工具库**：三视图与部件图、重贴图分组、对应面恢复 UV、素体权重迁移、表情拟合、SpringBone 检查。本路线和它有两处关键不同：头身不分开生成，以及整体生成一次只调用一个、不抽卡（都见第 2 步）。顺序上也不同：先确认结构和骨架，再做最耗时的重贴图。

## 推荐路线（逐步）

| 步 | 做什么 | 关键要求 / 参考 |
| --- | --- | --- |
| 1 | **设定图**：整理用户立绘，得到同一姿势、同一尺度的 T 型正面和背面（侧面可靠才加） | 两张图的脚底基线、头顶、臂展像素对齐；尾巴、翅膀这类可以后装的部件先去掉；背面头发用已认可的版本。Charakuru 的 `character-three-views` 可以参考 |
| 2 | **整体一次生成**：用 multiview_to_model 一次生成整个人物（含头、头发、身体、衣服） | 本地有效参数：face_limit 25000、quad、texture detailed、pbr false，只给正背两张图。**不要把头和身体分开生成**。**每次只提交 1 个生成任务，不并行，也不多次抽卡**：整体生成非常耗积分；等这一个检查完、确认需要时才重新生成（和 Charakuru 一次出多个候选再挑的做法不同） |
| 3 | **灰模 + 网格结构检查，并当场试拆组件** | 拿到模型立刻看灰模和线框，手动检查各部分网格是否合理，并**在这一步就尝试拆出头、头发（含刘海）、饰品、裙子等组件**，看拆完的效果。比如刘海和头、头发和脸、裙子和腿粘成一块拆不开，或者拆开后缺面、破洞，就说明这次网格不合格，要改设定图后重新生成（仍然一次一个），不要带着问题往后做。原生贴图也在这一轮一起看。组件要拆细，清单与拆法见 [component-texturing.md](component-texturing.md) |
| 4 | **快速绑定 + 骨架校验** | 结构通过后马上绑定，这一步花时间少、能很快发现问题。T 型模型可以用 Charakuru `avatar-weight-transfer` 做素体权重迁移，见 [rigging-physics.md](rigging-physics.md)。然后套一段现成的简单 MMD 动作（例如《愛包ダンスホール》），检查肩、肘、腕、手指、膝、颈有没有扭曲或撕裂，裙子和头发有没有跟错骨骼；发现问题就让 AI 修骨骼节点位置和权重，修好再往下做 |
| 5 | **Tripo 重贴图**（最耗时间，放在结构和骨架都确认之后）：对拆好的部件做保形重贴图，再把 UV 转回原网格 | 分组参考 Charakuru 五组（hair / head / upper_body / lower_body / accessories），见 [texture-transfer.md](texture-transfer.md)、[texture-refinement-qa.md](texture-refinement-qa.md)。网格、原 UV、法线、权重保持不变。**按组件选方法**（Tripo / Codex 投影 / 几何生成 / 平涂），送 Tripo 前先自展 UV，见 [component-texturing.md](component-texturing.md) |
| 6 | **表情、眼睛与嘴部** | 三样缺一不可：① 用 Charakuru `avatar-expression-authoring` 的方法论；② 目标角色的脸型不变；③ 有一个参考角色的完整表情网络（形态键）和贴图/口腔结构。没有参考角色就先找用户确认，不要直接开始做，否则表情不对、嘴部全乱。详见 [facial-expressions.md](facial-expressions.md) 开头的“前提”，以及 [eye-brow-expression-workflow.md](eye-brow-expression-workflow.md)、[mouth-transfer-vmd-repair.md](mouth-transfer-vmd-repair.md)、[eye-refinement.md](eye-refinement.md) |
| 7 | **物理**（最后做）：衣服和头发 | SpringBone（Charakuru `avatar-spring-setup`）或 Houdini（[houdini-cloth-hair.md](houdini-cloth-hair.md)、[houdini-fullsong-remote.md](houdini-fullsong-remote.md)）。依赖最终网格和骨架，所以放在最后 |
| 8 | **精细渲染与交付** | 前面各步都用原神式快速材质加灰模检查（见下文）；到这一步才用 [genshin-blender-render](https://github.com/CXP-2024/genshin-blender-render) 做精细渲染。之后再交付：静态模型、编辑工程、预览和缓存分目录；已完成和未完成的项目逐项如实报告 |

**顺序的理由**：越便宜、越快能发现问题的检查越往前放。网格结构不对就只能重新生成，而骨架问题套一段动作就能暴露；先把这两样确认好，再花大量时间做重贴图和表情，最后做依赖最终网格与骨架的物理。这样不会在一个结构有问题的模型上白做贴图。

### 为什么不把头和身体分开生成（和 Charakuru 不同）

Charakuru 原版是分别生成“带全部头发的头”和“T 型身体”两组候选，再拼起来。在本地实际制作中，这条路的拼接一直做不好：

- 两次生成的颈部截面、粗细和法线对不上，焊接后颈部出现接缝、锯齿或台阶；
- 头身比例和朝向要人工反复调，头一转动就会露馅；
- 两套贴图的肤色和光照不一致，颈部会有明显色差；
- 两边的拓扑没有对应关系，很难做出连续的皮肤，也就不好绑骨和刷权重。

整体一次生成时，头、颈、身体本来就是一张连续的网格，比例也一致。需要分件时，在这张网格上拆分（第 3 步试拆），再用重贴图补细节（第 5 步）。只有用户明确要求按 Charakuru 原流程制作时，才走分头身路线，并且要说明颈部焊接是主要风险。

## 制作期间默认用原神式快速材质

二次元角色在制作和迭代期间（拆件、绑定、重贴图、表情、物理检查），默认用一套简单的原神式三渲二材质，不要每次都上精细渲染：

- **做法**：贴图颜色 × 两色阴影。Diffuse → Shader to RGB → 灰度 → smoothstep（约 0.03–0.09）得到明暗分界；暗部乘上皮肤、头发、布料各自的阴影色，可再加一点边缘光。眼白、虹膜保持无光照。全部材质无光照的版本可以用 `scripts/component_tex/unlit_all.py`。
- **好处**：EEVEE 下渲染很快，检查一帧只要几秒；外观也接近最终的原神风格，看贴图、表情和穿模不会被复杂光照干扰。和灰模一起，构成每一步的标准检查。
- **只在最后一步**才用渲染 skill [genshin-blender-render](https://github.com/CXP-2024/genshin-blender-render) 做精细渲染：面部 UV 阴影、眼睛分层、服装 ramp、原生 MMD 描边、合成。精细渲染期间如果发现模型问题，回到对应步骤修，再用快速材质确认。

## 经验与禁忌

- **已认可的模型不重新生成**。原文件只读，修改存新副本；改贴图时网格、UV、权重、形态键都不动。
- **不要把 Charakuru 的权重迁移强套在已经完成的 A 型模型上**。Codex 这样做过，失败了。素体迁移要求 T 型输入，要用就按完整流程准备；否则沿用现有骨架和权重做局部修正。
- 设定图在提交前先对齐：两张图的臂展、基线、头顶要一致（本地做过“手臂区段水平压缩到与正面同宽、头发和裙子不动”）。图上标注了正、侧、背，不等于真的是同一姿势。
- **表情不能凭空做**：必须有参考角色的表情网络和贴图，用 Charakuru 方法迁移到不变的原脸上。没有参考角色的表情网络就去推顶点、只建命名滑块，或者用重新生成的网格来做，DeepSeek 都试过，结果是表情不对、嘴部全乱。
- 尾巴、翅膀这类部件后装：先核对原生件的根部、尖端和轴向，再缩放、旋转到真实的连接位置。
- 每一步都要看灰模：结构问题（后脑鼓包、颈部锯齿、指缝粘连、裙子穿模）在贴图渲染里容易被盖住。
- **生成不抽卡**：整体生成每次只提交一个任务，绝不并行，也不为了挑结果连续多抽。先认真检查这一次的结果，确定是设定图或参数的问题、改好后再生成下一次。
- 生成和修改都存新版本目录，记录 Tripo 任务 ID、请求参数和输入图，方便以后从同一个起点重做。

## 参考与生成细节

保存用户选定的完整设计，分清官方角色设定、社区设计和生成式参考。拆件和重绘不能改变原角色的胸腰、脸型或发型；用眼线、下巴、领口、腰线、裙摆、鞋底核对比例。画布尺寸不能代表物理尺度。

参考应清楚干净，但不等于抹掉所有色层：保留采用设计的发色层次、局部血色与装饰，去除环境投影、强色光和已移除部件的残影。反复重绘仍对不上时，保留原参考约束，改为可控的局部网格修正，不宣称已经精确复刻。

生成选项以当前代理 `models` 和 OpenAPI 为准。官方 Studio 的局部修复、拓扑或 UV 功能未必在代理开放，不要猜测不存在的端点。

## 装配与校准

Body、Head、Hair 等分别命名，可以选择是否保留为独立对象。没有必要一开始就把所有对象强制合并。连续皮肤本来就来自同一网格；独立的头发和服装可以共用骨架。

保留有效的 UV、材质和骨架。调姿势优先用骨骼或局部旋转；不要用按高度整体压缩网格来代替关节旋转，否则手臂轴会弯。刘海局部形状不对就修发束，不靠整体平移头发掩盖。

## 认可外形后的修复

- 区分生成部件、可选对象、贴图分组、物理链和表情选区。分开命名或生成，不保证拓扑独立，也不保证贴图独立。脸、头发、眼球、眉毛的真实面归属，要单独显示加灰模来确认，不能只看颜色或连通块大小。
- 比较新旧模型时固定投影和画幅，不能非等比拉伸图片来伪装脸型吻合。脸要看正面、左右斜面和侧面；原版不动时，只拟合新部件。
- 重拓扑是为了变形，不是为了把三角面换成更多四边面。外形已经好时，先判断眼、口边缘的布线够不够；只整理编辑区就行时不重建整个头。需要新拓扑时，在副本上建立眼口环线、贴合原表面并转移纹理，再检查轮廓和局部表面误差。
- 头发要覆盖住头部，不能是悬空的壳；长发根部到发束的过渡和侧面距离都要检查。用户要求裙子不动或允许局部穿模时照做。
- 不要把另一个头的眼睛贴片只在正面缩放对齐后，就称作三维移植；更不能把多次生成的不同网格直接当作连续的表情键。

## 灰模与运动验收

输出正、侧、背以及左右手近景，检查：

- 肩、肘、腕连续，手掌厚度和腕部过渡正常，没有扭转或瘪陷；
- 每只手五指分明，拇指根清楚，指缝不粘连，没有用袖口代替手腕皮肤；
- 裙下、腋下、颈口和其他隐藏区域没有意外封死或缺面。

没有骨架的静态灰模只能证明静态几何没问题，不能说动作通过。动作失败时，按局部几何、权重、骨架方向分别排查。

## 材质、表情与交付

保留已有的正确贴图，只有几何变了、UV 不再适用时，才重新展开或烘焙。做三渲二时，要检查贴图里自带的明暗、材质分区和脸部阴影；自动生成的 PBR 不等于目标风格。

连续眨眼和口型需要真实的眼睑、口腔和可变形的面部拓扑，只有命名滑块不算完成。MMD 还需要骨骼命名和映射、IK、手指权重、表情以及衣服和头发物理。逐项报告实际完成情况和残留差异。静态分享包可以只含完整模型和必需贴图。

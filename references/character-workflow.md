# 参考驱动的人物建模：推荐路线与经验

来源（核对于 2026-10-19）：
- [Tripo 官方 GPT-6 Astra 角色流程](https://www.tripo3d.ai/blog/gpt-6-astra-3d-character-workflow)
- [Tripo 官方 P2 游戏角色教程](https://www.tripo3d.ai/blog/mesh-game-character-p-2)
- [Charakuru](https://github.com/nanocle/Charakuru)：从一张立绘做到可动 VRM 的完整套件，包括部件图、三视图、Tripo 候选、重贴图、素体权重迁移、表情和摇摆物理。方法和源码入口见 [charakuru-methods.md](charakuru-methods.md)。

下面的路线来自本地 DeepSeek 鲸娘多轮制作（2026-10-19 至 10-29）的实际结果，不是官方逐步保证。官方页的角色图片、问候动画和面部特写是分开的展示资产，不能当成同一次生成的端到端质量保证。

## 0. 先装好 Charakuru 源码

开始造新角色前，先确认本机有 Charakuru 源码：

1. 到 GitHub Releases（`nanocle/Charakuru`）下载最新发行版 zip，解压到一个独立的 kit 目录，不要在只读参考副本里制作。
2. 准备运行环境：Node.js 22 以上（启动不需要 `npm install`）、Blender 5.2、VRM Add-on for Blender。Blender MCP 可选，没有时用无界面 `blender -b --python` 执行它自带的脚本，并如实说明。
3. 阅读入口：`AGENTS.md`（写给 Codex 的流程、确认点和保存规则）和 `skills/` 下的 9 个 skill。用 Claude Code 时，在 kit 里加一个 `CLAUDE.md`，写明工具名对应关系（image_gen → 本机生图 skill，浏览器操作 → Claude in Chrome，Blender MCP → 无界面 Blender）。
4. 需要用它的界面时，在 kit 目录 `npm start`，打开 `http://127.0.0.1:8766`。

版本号、素材许可和第三方说明见 kit 里的 `LICENSE` 和 `THIRD_PARTY_NOTICES.md`。复制或发布之前先核对；不要把它的人体、表情素材打包进其他仓库。

Charakuru 用作**方法和工具库**：三视图与部件图、重贴图分组、对应面恢复 UV、素体权重迁移、表情拟合、SpringBone 检查。本路线和它有一处关键不同，见第 2 步。

## 推荐路线（逐步）

| 步 | 做什么 | 关键要求 / 参考 |
| --- | --- | --- |
| 1 | **设定图**：整理用户立绘，得到同一姿势、同一尺度的 T 型正面和背面（侧面可靠才加） | 两张图的脚底基线、头顶、臂展像素对齐；尾巴、翅膀这类可以后装的部件先去掉；背面头发用已认可的版本。Charakuru 的 `character-three-views` 可以参考 |
| 2 | **整体一次生成**：用 multiview_to_model 一次生成整个人物（含头、头发、身体、衣服） | 本地有效参数：face_limit 25000、quad、texture detailed、pbr false，只给正背两张图。**不要把头和身体分开生成** |
| 3 | 灰模 + 原生贴图，看正、侧、背，与设定图对比 | 第一轮就要看贴图：画进皮肤的阴影、双尾巴、假袖子要在这里发现 |
| 4 | **在同一网格上拆分结构** | 头发、前发、裙子、饰品、五官小件按需分成独立对象；补后脑等被遮挡的区域。拆分只改归属，不移动顶点，所以接缝保持原样 |
| 5 | **Tripo 重贴图**：对拆好的部件做保形重贴图，再把 UV 转回原网格 | 分组参考 Charakuru 五组（hair / head / upper_body / lower_body / accessories），见 [texture-transfer.md](texture-transfer.md)、[texture-refinement-qa.md](texture-refinement-qa.md)。网格、原 UV、法线保持不变 |
| 6 | 表情与眼睛 | [eye-brow-expression-workflow.md](eye-brow-expression-workflow.md)、[facial-expressions.md](facial-expressions.md)、[mouth-transfer-vmd-repair.md](mouth-transfer-vmd-repair.md)、[eye-refinement.md](eye-refinement.md)；方法来自 Charakuru `avatar-expression-authoring` |
| 7 | 骨架与权重 | T 型模型可以用 Charakuru `avatar-weight-transfer` 做素体权重迁移，详见 [rigging-physics.md](rigging-physics.md)。之后做抬臂、屈肘、转头、屈膝、握拳和短动作测试 |
| 8 | 衣服和头发物理 | SpringBone（Charakuru `avatar-spring-setup`）或 Houdini（[houdini-cloth-hair.md](houdini-cloth-hair.md)、[houdini-fullsong-remote.md](houdini-fullsong-remote.md)） |
| 9 | 交付 | 静态模型、编辑工程、预览和缓存分目录；已完成和未完成的项目逐项如实报告 |

### 为什么不把头和身体分开生成（和 Charakuru 不同）

Charakuru 原版是分别生成“带全部头发的头”和“T 型身体”两组候选，再拼起来。在本地实际制作中，这条路的拼接一直做不好：

- 两次生成的颈部截面、粗细和法线对不上，焊接后颈部出现接缝、锯齿或台阶；
- 头身比例和朝向要人工反复调，头一转动就会露馅；
- 两套贴图的肤色和光照不一致，颈部会有明显色差；
- 两边的拓扑没有对应关系，很难做出连续的皮肤，也就不好绑骨和刷权重。

整体一次生成时，头、颈、身体本来就是一张连续的网格，比例也一致。需要分件时，在这张网格上拆分（第 4 步），再用重贴图补细节（第 5 步）。只有用户明确要求按 Charakuru 原流程制作时，才走分头身路线，并且要说明颈部焊接是主要风险。

## 经验与禁忌

- **已认可的模型不重新生成**。原文件只读，修改存新副本；改贴图时网格、UV、权重、形态键都不动。
- **不要把 Charakuru 的权重迁移强套在已经完成的 A 型模型上**。Codex 这样做过，失败了。素体迁移要求 T 型输入，要用就按完整流程准备；否则沿用现有骨架和权重做局部修正。
- 设定图在提交前先对齐：两张图的臂展、基线、头顶要一致（本地做过“手臂区段水平压缩到与正面同宽、头发和裙子不动”）。图上标注了正、侧、背，不等于真的是同一姿势。
- 尾巴、翅膀这类部件后装：先核对原生件的根部、尖端和轴向，再缩放、旋转到真实的连接位置。
- 每一步都要看灰模：结构问题（后脑鼓包、颈部锯齿、指缝粘连、裙子穿模）在贴图渲染里容易被盖住。
- 生成和修改都存新版本目录，记录 Tripo 任务 ID、请求参数和输入图，方便以后从同一个起点重做。

## 参考与生成细节

保存用户选定的完整设计，分清官方角色设定、社区设计和生成式参考。拆件和重绘不能改变原角色的胸腰、脸型或发型；用眼线、下巴、领口、腰线、裙摆、鞋底核对比例。画布尺寸不能代表物理尺度。

参考应清楚干净，但不等于抹掉所有色层：保留采用设计的发色层次、局部血色与装饰，去除环境投影、强色光和已移除部件的残影。反复重绘仍对不上时，保留原参考约束，改为可控的局部网格修正，不宣称已经精确复刻。

生成选项以当前代理 `models` 和 OpenAPI 为准。官方 Studio 的局部修复、拓扑或 UV 功能未必在代理开放，不要猜测不存在的端点。

## 装配与校准

Body、Head、Hair 等分别命名，可以选择是否保留为独立对象。没有必要一开始就把所有对象强制合并。连续皮肤本来就来自同一网格；独立的头发和服装可以共用骨架。

保留有效的 UV、材质和骨架。调姿势优先用骨骼或局部旋转；不要用按高度整体压缩网格来代替关节旋转，否则手臂轴会弯。刘海局部形状不对就修发束，不靠整体平移头发掩盖。

## 认可外形后的修复

- 区分生成部件、可选对象、贴图分组、物理链和表情选区。分开命名或生成，不保证拓扑独立，也不保证贴图独立。脸、头发、眼球、眉毛的真实面归属，要单独显示加灰模来确认，不能只看颜色或连通块大小。
- 比较新旧模型时固定投影和画幅，不能非等比拉伸图片来伪装脸型吻合。脸要看正面、左右斜面和侧面；原版不动时，只拟合新部件。
- 重拓扑是为了变形，不是为了把三角面换成更多四边面。外形已经好时，先判断眼、口边缘的布线够不够；只整理编辑区就行时不重建整个头。需要新拓扑时，在副本上建立眼口环线、贴合原表面并转移纹理，再检查轮廓和局部表面误差。
- 头发要覆盖住头部，不能是悬空的壳；长发根部到发束的过渡和侧面距离都要检查。用户要求裙子不动或允许局部穿模时照做。
- 不要把另一个头的眼睛贴片只在正面缩放对齐后，就称作三维移植；更不能把多次生成的不同网格直接当作连续的表情键。

## 灰模与运动验收

输出正、侧、背以及左右手近景，检查：

- 肩、肘、腕连续，手掌厚度和腕部过渡正常，没有扭转或瘪陷；
- 每只手五指分明，拇指根清楚，指缝不粘连，没有用袖口代替手腕皮肤；
- 裙下、腋下、颈口和其他隐藏区域没有意外封死或缺面。

没有骨架的静态灰模只能证明静态几何没问题，不能说动作通过。动作失败时，按局部几何、权重、骨架方向分别排查。

## 材质、表情与交付

保留已有的正确贴图，只有几何变了、UV 不再适用时，才重新展开或烘焙。做三渲二时，要检查贴图里自带的明暗、材质分区和脸部阴影；自动生成的 PBR 不等于目标风格。

连续眨眼和口型需要真实的眼睑、口腔和可变形的面部拓扑，只有命名滑块不算完成。MMD 还需要骨骼命名和映射、IK、手指权重、表情以及衣服和头发物理。逐项报告实际完成情况和残留差异。静态分享包可以只含完整模型和必需贴图。

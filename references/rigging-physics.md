# 骨骼、权重、动作与物理

基于现有 Tripo 代理流程、Charakuru 源码和本地失败经验。Charakuru 的权重/SpringBone 方法尚未因此在每个本地角色验证；先检查实际资产与目标格式。静态展示不自动进入绑骨流程。

## 保留角色，取得可用骨架

- 已有可用身体骨架就复用，检查轴向、单位、rest pose、Armature 修改器和对象父级，避免双重变换。头/发/配件不因骨架导入改变原始摆放或贴图。
- Tripo 代理按主 skill 的 prerigcheck → rig → 状态/动作检查 → retarget 走；返回绑定成功不是权重和外观合格。只查模型时不提交动画。
- Charakuru 路线将头与带衣身体送去 rig，先保管头发；只导入恢复原尺度的骨配置，不用 Tripo 返回网格覆盖已经完成材质的基准部件。其脚本依赖 `.charakit` 状态；直接用于 Blender 项目需显式适配坐标和骨映射。
- Auto-Rig Pro、Rigify 或 Tripo 是骨架/绑定工具，不自动修 UV、口腔、表情或衣发物理。调用插件前检查实际安装与许可，不能凭名称承诺功能。

## 权重转移与局部测试

Charakuru 先把可用素体匹配到目标骨架，再用最近三角面插值转移权重。先看拟合素体的正/侧/斜面，特别是肩胸、腋下、股部、指间与关节中心。不要把别人的素体外形替换为角色身体；使用和交付第三方素体遵守对应许可。

转移范围按语义和空间约束：身体/衣服通常接收人体权重；裙摆、长发、尾巴等从自动身体转移中独立处理。宽裙离腿远、手贴近裙子、指间距离小，最近表面会误配。权重归一化和限制影响骨数只是技术检查（上游工具截取前四权重），并不保证正确骨头；按目标格式选择限制。

本地典型错误是动手臂把裙子扯走。检查裙片上 arm/hand 权重而不是先改物理。测抬臂、屈肘、握拳、转头、屈膝和简单步行，核对肩、腰、裙摆、发根是否被错误骨骼拖走。被暂时固定到 hips/head 的摆动物不能称为已设置物理。

### 先定位人体关节，再修服装权重

- 披肩外角、泡泡袖外轮廓、裙摆边界不是人体关节地标。肩关节应依据躯干、锁骨和上臂中心估计；衣服遮挡处明确是推测，不把自动骨架当作解剖真值。
- 诊断时暂时隐藏遮挡的头发，显示实际肩、肘、腕的世界坐标标记，检查正面与侧面。把“关节位置”“蒙皮权重”“静止服装形状”“测试姿势”分开判断；披肩不跟随不能直接证明肩骨位置正确。
- 对比使用相同的放臂、抬臂和屈肘角度。放松肘部可以改善观感，但不能作为绑定修复的证据。Claude 的独立抬腿测试曾固定上臂下转约 65°、前臂不弯，不能用它验收舞蹈手臂。
- 简单按世界轴坐标划分上臂/前臂权重只能作为初稿。重新定位肩肘后，重建肩部—上臂—前臂的连续影响范围；保留手指与袖口语义，避免饰品被手指牵引。披肩的跟随或物理另行处理。
- 修改 rest pose 后重新计算动作重定向所用的 rest 矩阵，不能直接复用旧骨架的局部旋转曲线并宣称已校准。骨骼长度、roll、父子变换与姿态补偿一并检查。
- 体型对照采用同一正交尺度、脚底对齐、同姿势和正/侧视图；重置衣发动态。记录是否缩放，区分含头饰总高度、骨骼地标与实际身体轮廓。穿衣模型的裙宽不等于胯宽。

Claude V22 的肩关节间距缩小约 25%、肘部略内移，是该角色的试调结果，不是其他角色的默认人体比例。用户接受继续测试，不代表遮挡下的人体位置已被精确验证。

## 摆动物理按用途设置

选择目标运行环境：VRM SpringBone、MMD 刚体/关节、Blender 骨链/布料各自验证；不声称使用了原神相同的内部求解器。用实时弹簧骨与碰撞实现相近观感是一种方案，复杂布料需求另评估。

- 根部锚定，向末端连续分布权重；长发不能整束像刚板翻起，也不能在固定头壳与活动长发间留下硬接缝。刘海、侧发、长发分范围处理。
- 裙腰固定，裙摆需要足够的环向/纵向自由度与合适的链或模拟网格，不能把整裙仅绑成一块刚体。腿/胯碰撞与层叠裙片要按实际裙型检查。
- 尾巴以已采用的曲线为静止姿态，根部接在正确位置，沿长度连续刚度与阻尼；避免为防穿模将整尾横抬或仅改后半段。用户允许穿模或禁止改裙子时保持其约束。
- 碰撞体只覆盖需要区域，过大导致离身悬浮，过小或缺失会穿透。按实际单位设置碰撞半径，不能把上一模型的数值原样复制。
- 高速旋转或跳跃中若甩到近水平/九十度、裙摆刚硬，分别检查角速度、惯性、阻尼、刚度、约束、时间步/子步与碰撞；不要只靠缩小动作或提高刚度掩盖问题。

### Charakuru / VRM 的具体经验

读 `avatar-spring-setup` 与 `scripts/spring-setup.py` 后再用。其配置区分 chains 和 targets，各目标明确 spring/fixed；记录固定原因，不把尚未设置的部分充作固定完成。

VRM 1.0 链末节点用作末端位置，上游脚本会为变形骨补非变形终端骨；已有末端时按该版参数声明，避免重复添加。设置同名链需可重入，不破坏其它链、人体骨架与权重。

`center` 会改变惯性的参考坐标：把 head 设为头发 center、hips 设为裙子 center 可能抵消期望的父骨运动。不要总填父骨；仅在明确需要抵消移动时设置，并通过行走响应检验。脚本重力方向采用 Blender 坐标，导出轴转换由格式处理，不手工重复旋转。

## 动作和验收

### 已验证的本地接入方式（DeepSeek 试跑）

现有可用骨架不必重新调用 Tripo。实际试跑复用原骨架与权重，用 `avatar-weight-transfer/scripts/transfer.py:human_map` 映射 humanoid，`scripts/spring-setup.py:setup` 注册链，再通过 `scripts/mtoon-export.py:apply_mtoon` 导出。此次未运行供体权重转移，不能将此试跑算作完整自动绑骨验证。

动作使用 `public/preview-avatar.mjs` 的 PreviewAvatar 播放项目自带 `public/elyth_base_walk_v1.vrma`，以固定 60 Hz 连续求解；同步显示物理关闭/开启，录制正、斜、侧面。自带动作是重定向测试素材，分享时核对素材许可。导出的 Blend 只有骨架和物理配置时，必须说明 VRMA 在运行时播放、尚未烘焙进 Blender。

DeepSeek 此次验证了 36 条有效链、7 个身体碰撞体、144 个运行时关节及实际网格响应；这些数值和刚度仅属于此资产。未验证高速转身、跳跃和尾巴对裙子的专用碰撞。表情键保留不等于 VRM expression 映射已完成；内部 review 元数据也不等于可以直接发布。

导出前同时检查 Blender 节点和 MToon 扩展记录的基色图片：节点已换图但扩展仍指向旧图，会导致 Blender 与 VRM 外观不一致。以明确采用的基色节点重建导出材质，并检查 UV、透明度与法线采样。实时预览需正确的 mipmap/minFilter 和各向异性，避免采样闪烁；这不能修复原贴图瑕疵。保存后新进程核对几何、原 UV、权重、形态键、驱动和打包图片。

重定向先匹配人体骨映射、rest pose、左右、根运动与 IK。已有动作文件不能只按同名骨盲套；检查脚底滑动、身体漂移、手臂翻转和裙发误跟随。

### 动作、缓存与验收分层

- 查实际网格的 Armature 修改器指向，不按场景内相似名称猜骨架；Claude 工程保留了供体和旧骨架。VMD 复用时保留采样区间、插值、根位移和音轨偏移记录。项目中的 34° 手臂静止姿态补偿只属于对应供体/目标组合，不是通用 VMD 常数。
- 建立独立测试动作时清理旧动画并显式创建新 Action，避免旧关键帧混入。先做局部关节测试，再接真实舞蹈；FK 腿动作不能标成已验证足部 IK。
- 烘焙到 MDD/Alembic 后，画面可能已由缓存驱动，编辑骨架或权重不会自动更新画面。明确当前显示的是骨骼变形还是绝对顶点缓存，并防止两者叠加。
- 静态抬腿缓存不能用于不同舞蹈。只有已证明某部位在整个测试中保持同一姿态，才可用该部位的恒定位移差修补缓存；不能把这种局部便捷方式推广到动态手臂或新动作。
- 缓存校验包括实际计算帧数、顶点数/顺序、坐标轴与单位、有限数值、重开工程后路径有效，以及未修改部位的逐帧差异。填充末帧的预览缓存必须单独命名，不能冒充整段已解算。
- 同步提供同帧、同镜头的物理开/关或修复前/后对照，并看灰模、材质和必要的局部近景。数值通过、抽帧检查、完整视频解码、用户认可分别记录，不互相替代。

Houdini/Vellum 的模拟网格、动态锚点、头发连续过渡与缓存实现见 [houdini-cloth-hair.md](houdini-cloth-hair.md)。这是本地补充流程，不应称为已运行 Charakuru 官方完整物理流程。

比较物理 ON/OFF 的真实运行时顶点响应。上游 `verify-springs.mjs` 对导出的 VRM 做 90 帧部位响应对照，可发现无效权重、缺链和不响应配置；通过该检查仍不证明不穿模或观感自然。

根据任务输出短步行、转身及必要的跳跃/快速转身测试，看起动、停止、落地后的回弹与稳定，不只看一帧。**相机绕静态人物转圈不产生角色运动惯性**，不能用 turntable 当物理测试。随机跳帧截图不能代替连续求解；缓存/烘焙与固定时间步应和交付动画一致。

保存后在新进程重新打开，并在目标格式/播放器复测。FBX 不是 MToon 或 VRM SpringBone 的完整设置容器；保留配置在 Blend/VRM 中。MMD 需另外核对骨名、IK、刚体、关节和 morph；“有 Blender 骨架”不等于 MMD 即用。

交付时分开写：骨架有效、权重变形、动作重定向、物理响应、碰撞观感、贴图与导出，各项已测/未测/遗留问题。用户只要演示时先做短片，不默认租 GPU 或跑全长高成本动画。


### 动画中的材质回归检查

动作接入后若五官消失、肤色覆盖范围漂移，不先换打光。检查修补材质是否用 Geometry Position 的世界坐标范围作为遮罩；物体平移、转身、转头与蒙皮后该区域不再对应原部位。按 [texture-refinement-qa.md](texture-refinement-qa.md) 固定到 UV 或静止位置属性，保留原外观。末端 Emission 可能接收 Shader to RGB 的受光结果，不能据此断言无光照。

# 保持原脸的表情制作

适用：已有认可中性脸，希望便于编辑眼、眉、口并实现连续变形。以 Charakuru 1.1.0 的眼周面罩、上下口缘与独立眉迁移为起点，源码定位见 [charakuru-methods.md](charakuru-methods.md)。

## 前提：三样都要有，缺一不做

眼睛、嘴部和表情的制作**必须同时满足**以下三点。缺任何一点，做出来的表情就不对，嘴部会完全乱掉。

1. **方法用 Charakuru**：使用 `avatar-expression-authoring` 的方法论，包括眼周皮肤面罩、上下口缘分开迁移、左右眉独立；先拟合，目视确认后再迁移；所有改动都写在工作键上。源码定位见 [charakuru-methods.md](charakuru-methods.md)。
2. **目标角色的脸型不变**：Basis、原 UV 和材质不改；所有表情键归零时，必须回到原来的中性脸。鼻梁、脸颊、下颌、眼距、脸宽都不能为了贴近参考而改动。
3. **必须有一个参考角色的完整表情网络和贴图**，可以是用户指定的 MMD/PMX 角色，例如原神奥黛塔。
   - **表情网络**：眨眼、单眼闭、笑眼、情绪眼，各种眉形，あいうえお、ん（闭嘴）、口角上下等实际在用的形态键。
   - **配套贴图和结构**：真实口洞、口缘、口内、牙、舌、眼睑线、闭眼时的睫毛、眼白/虹彩/高光的分层。
   
   参考角色决定“表情怎么动、做完是什么样子”；Charakuru 决定“怎样迁移才不改变原脸”。Charakuru 自带的表情库（8 种眼、10 种嘴、5 种眉）只提供动作姿势，不能代替参考角色的口腔结构和贴图。

**没有参考角色时，不要直接开始做**：先向用户确认参考角色，或者请用户提供一个。只靠命名滑块、在原网格上推顶点、或者拿 Tripo 重新生成的网格来做，都会得到错误的表情；嘴部尤其会乱，因为没有真实的口腔结构和口内贴图。

嘴部做法：从参考角色移植口缘、口内、牙、舌的局部结构及其贴图，与目标脸的接缝只在外围过渡。见 [mouth-transfer-vmd-repair.md](mouth-transfer-vmd-repair.md)。眼眉做法见 [eye-brow-expression-workflow.md](eye-brow-expression-workflow.md)，眼睛分层贴图见 [eye-refinement.md](eye-refinement.md)。

## 原脸与选区

原本、Basis、原有 UV/面/法线/材质/权重/形态键保留；工作副本新增键。全键归零应回到原版中性脸。按模型保存选区和地标，并对照 Basis 与拓扑签名；不把本次顶点编号用于另一个模型。

先显示带发自然脸，再单独显示皮肤、睫毛、眉毛、虹彩/高光、眼睑线、真实口缘。灰模和线框确认几何，材质渲染确认印象。用区域颜色标记核对正、左右斜、侧视图；颜色阈值、包围盒、连通块数量只能辅助，不能作最终语义选区。

一个游戏式可编辑头部需要能独立控制的功能区，但不要求每个区都另存一张贴图。分离对象、UV 岛、绘画遮罩和形态键影响区各有用途。若原网格确实没有口洞/合适眼睑结构，说明所需局部拓扑工作；不要把整理选区说成完成重拓扑。

## 眼部迁移

眼眉续作与参考复刻时，先读 [眼眉制作与对照流程](eye-brow-expression-workflow.md)。它补充 Charakuru 源码调用、保留原脸的局部修形、同权重左右灰模/渲染验收和 VMD 接入；本地未通过的试验不能作为完成范例。

1. 固定相机，确认 front/up 与角色左右。用该模型的皮肤 seed 识别眼周面罩；每眼内、外、上、下四点放在皮肤开口边，不是虹彩外周或睫毛尖。
2. Charakuru 工具顺序是 `prepare_blink` → `set_blink_points` → `set_blink_followers` → `fit_blink` → `capture_fit`，目视确认后才 `transfer_eyes(reviewed=True)`。调用参数看版本对应 `references/transfer.md`，不要把示例占位符当真实选区。
3. 睫毛与需要的眼睑线作为追随部件，眉不加入普通眨眼追随。虹彩和高光按实际结构处理，检查中间值是否穿出、缩小或消失。
4. 该版本源闭眼姿势主要上下移动，八点拟合不保证深度正确。侧面检查眼睑是否贴合头面曲率、睫毛是否悬浮；修复前后方向，不只平滑正面轮廓。
5. 上睑主导、下睑少量运动是起点，不固定套用比例。变形分散到多行皮肤，眼角衰减，避免整条睫毛平移或仅拉长一排网格。保留自然脸的眉位，情绪眉另作键。

上游有 8 个眼部、5 个眉部与 10 个嘴部姿势，可按用户范围选用；数量不是完成标准。多次 API 生成的不同头部既没有稳定顶点对应，也不能靠切换局部模型得到可编辑连续 Shape Key。

## 嘴部与眉部

- 嘴：先确认真实口洞和上下口缘，两条弧共用口角、内部顶点不共用。用 `mouth_paths` / `prepare_mouth` / `capture_mouth_fit` / `transfer_mouth` 分别迁移上下弧，再沿连接皮肤分散位移。全口最近面 Surface Deform 容易把靠得很近的上下唇混在一起。
- 不按整体平均高度分上下唇，也不把贴图的一条线当口洞。没有开口时不能声称迁移已经建立正常口腔；新增口缘/口内属于明确的结构制作，不靠灰片、黑贴片遮丑。
- 眉：用 `prepare_brows` / `transfer_brows` 对左右独立部件适配曲线；皮肤需要跟随时另设保护眼缘与衰减范围。眉与皮肤连为一体时可局部编辑，不默认强制切开。
- 再次迁移可能覆盖同名键的局部修正，先保存已修状态。脸部不对称拓扑不能直接假定镜像顶点一一对应。

## 双眉与双眼睑线的诊断

本地出现过两种不同问题：脸图中画了一份眉/眼睑线，另有独立网格；以及独立眼睑线只跟眨眼、不跟怒眼/眉部表情。前者检查并清掉多余纹理，后者给实际局部皮肤变形建立跟随。不能看到两条线就一律擦掉，也不能只试 blink 就判定其余键跟随正确。

按目标三维面投射清理遮罩，保护虹彩、眉、睫毛和不相关肤色。避免用全图颜色删除导致蓝眼蓝眉一起丢失。头发上的肤色先查面归属及 UV，不能用脸部修图方法随便涂蓝。

## 验证与交付

- 先看代表闭眼、单眼闭合、怒眉和张嘴，纠正公共拟合后再批量制作。按本次要求测试 0、0.5、1 强度及连续变化；眼口眉组合检查相互拉扯。
- 灰模看折痕、翻面、脱离、口内与眼球穿透；同相机带纹理看原版精致度与身份。既看正常展示尺度，也看问题近景。
- 带发与隐藏头发两种都看，不能只用刘海遮缺陷。默认不为表情改变全脸比例或中性脸。
- 保存后重新加载，检查驱动连接实际 Shape Key；测试控制器 0/中间值/1 与归零结果。导出 GLB/VRM/PMX 时核对真实 morph 和格式绑定，Blender 自定义属性不会自动成为每个格式的标准表情。
- 交付可编辑模型、实际演示和简短已知问题。DeepSeek 本地眼眉已能演示但睫毛仍有折角；嘴部迁移和 VMD 接入的后续验证见下文。不能把局部结果写成全部表情或全部游戏格式已验收。
